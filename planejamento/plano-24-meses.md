24-Month Cybersecurity Education Plan

From Beginner to Advanced Professional Competence

Program duration: 24 months
Estimated schedule: 104 weeks
Weekly study commitment: 15–17 hours
Total estimated workload: 1,560–1,768 hours
Current level: Beginner
English level: Intermediate
Primary study environment: Linux / Termux(Android)
Programming language: Python
Version control: Git and GitHub

---

1. Program Vision

This program is designed to build a strong foundation in Computer Science and Cybersecurity, progressing from fundamental concepts to advanced practical competencies.

The objective is to develop the technical knowledge, practical experience, analytical thinking, professional discipline, and communication skills required to pursue an international career in cybersecurity.

The program combines academic foundations, hands-on laboratories, independent projects, technical documentation, and professional development.

Important: Completing this program does not automatically make someone an internationally recognized cybersecurity specialist. Recognition comes from demonstrated competence, meaningful projects, professional experience, research, and continuous contribution to the field.

---

2. Main Objectives

By the end of the 24 months, the student should be able to:

1. Understand fundamental Computer Science concepts.
2. Write, debug, and maintain Python programs.
3. Work confidently with Linux environments and command-line tools.
4. Understand computer networks, protocols, and network security.
5. Explain operating system architecture and fundamental security mechanisms.
6. Identify common vulnerabilities in applications and systems.
7. Apply secure programming principles.
8. Perform authorized security assessments in controlled environments.
9. Understand defensive security, monitoring, and incident response.
10. Work with fundamental cloud security concepts.
11. Document technical investigations and communicate findings.
12. Build a verifiable cybersecurity portfolio.
13. Read technical documentation and communicate technical concepts in English.
14. Prepare for selected entry-level and intermediate professional certifications.

---

3. Learning Methodology

The program follows a practical, cumulative learning model.

Activity| Weekly allocation
Theory and technical reading| 4 hours
Programming and technical exercises| 3 hours
Practical laboratories| 4 hours
Projects and documentation| 2 hours
Review and assessments| 1 hour
Technical English| 1–3 hours
Total| 15–17 hours

The allocation may change according to the difficulty of each subject.

Learning cycle

Each subject follows this sequence:

1. Learn the concept.
2. Study a practical example.
3. Execute guided exercises.
4. Perform an independent laboratory.
5. Document the results.
6. Complete an assessment.
7. Review mistakes and reinforce weak areas.

Evidence-based learning

Every week must produce evidence of learning, such as:

- Markdown notes.
- Solved exercises.
- Python scripts.
- Terminal command records.
- Laboratory reports.
- Screenshots when appropriate.
- Git commits.
- Technical English exercises.

- Basic data structures.

- Write simple Python programs independently.
- Understand basic algorithms and logical operations.
- Use Git for version control.
- Maintain organized technical notes.
- Explain fundamental programming concepts.

Main subjects:

6. Practical Laboratory Policy

All practical activities must follow legal, ethical, and professional standards.

The student must:

- Work only on systems they own or have explicit authorization to test.
- Use intentionally vulnerable applications and controlled laboratories.
- Avoid unauthorized scanning, exploitation, access, or data collection.
- Protect credentials, private keys, tokens, and personal information.
- Document the scope and authorization of security tests.
- Prioritize remediation and responsible disclosure.

The objective is to develop professional security skills, not to compromise systems without permission.

7. Evaluation and Progression Criteria

Progress is measured by demonstrated competence, not simply by time spent studying.

Each week should include:

- Completion of assigned lessons.
- Exercises and practical activities.
- Technical notes.
- Evidence of execution.
- A short review or assessment.
- Technical English practice.

Suggested performance scale

Score| Status| Meaning
90–100%| Excellent| Strong understanding and independent execution
80–89%| Approved| Competent performance
70–79%| Conditional| Review and reinforcement required
Below 70%| Not approved| Re-study and reassessment required

A phase should be considered complete only when its essential competencies have been demonstrated through practical evidence and assessment.

---

8. Portfolio and Documentation Standards

All relevant work must be organized in the GitHub repository.

The repository should contain:

- The main program overview.
- The 24-month plan.
- The curriculum.
- The general schedule.
- Weekly study records.
- Programming projects.
- Laboratory reports.
- Security assessments.
- Technical documentation.
- Final projects.

Never publish passwords, API keys, private keys, access tokens, personal data, or confidential information.

The portfolio must demonstrate the student's actual work. Do not claim skills, certifications, or experience that have not been earned.

---

9. Certification Strategy

Certifications are supporting milestones, not substitutes for practical competence.

Potential certification paths will be evaluated according to:

- Current knowledge level.
- Prerequisite skills.
- Professional objectives.
- Cost and accessibility.
- Recognition in the target job market.
- Practical value of the certification.

Certification choices and exam versions must be reviewed when the student approaches the relevant stage. No certification is guaranteed by completion of this program.

---

10. Final Success Criteria

At the end of the 24-month program, the student should have:

- A structured foundation in Computer Science.
- Practical Linux and networking skills.
- Python programming experience.
- Knowledge of fundamental security principles.
- Experience with defensive security workflows.
- Experience with authorized offensive security laboratories.
- Basic cloud security and DevSecOps knowledge.
- A selected specialization path.
- A documented portfolio of practical projects.
- Technical reports written to professional standards.
- Improved technical English.
- A realistic plan for continued professional development.
